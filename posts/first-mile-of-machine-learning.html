The first mile of machine learning

Starting graduate school, opening Andrew Ng’s course, and learning to frame a problem before solving it.

14 June 2023 4 min read Learning Notes

Before graduate school, I thought machine learning was a collection of algorithms. The first few weeks of Andrew Ng’s course changed that. It is not mainly a collection of algorithms; it is a way of stating a problem so that data can answer it.

Supervised learning: answers first

Supervised learning starts with labeled examples: an input and the answer you want the model to produce. Regression predicts a continuous value — a price, a temperature, a coordinate. Classification chooses among discrete labels — spam or not spam, infected or healthy.

The distinction sounds academic until you have to describe your own problem. Are you predicting a number or a category? What counts as a correct answer? How would a wrong answer fail? Those questions come before the choice of model.

Unsupervised learning: structure without answers

Unsupervised learning works without labels. Clustering groups examples that resemble one another; recommendation systems and customer segmentation are familiar applications. The cocktail party problem — separating overlapping voices from a recording — is another example of finding structure without being told what the structure should be.

The absence of labels does not mean the absence of evaluation. It means you have to define what “good” means. That is harder than it sounds, and it is where a lot of projects quietly go wrong.

What actually stayed

Frame the task before choosing the model. A clever model applied to the wrong question produces a confident answer to nothing.

The data is part of the algorithm. Who collected it, what is missing, and which cases were never recorded matter as much as the architecture.

A metric is a value judgment. Accuracy, precision, recall, and mAP encode different ideas about what a mistake costs. Choosing a metric is choosing what to care about.

Start simple. A linear baseline that you understand is more useful than a complicated model you cannot debug. Complexity should earn its place.

The part I did not expect

I expected the mathematics to be the hard part. It was not. The hard part was developing the habit of asking: what exactly am I predicting, from what evidence, and how would I know if I were wrong?

That habit is still the most useful thing I took from the course. It is also the reason I keep a notebook. The model changes; the questions tend to stay.

Note. First published on VectorBlog in June 2023. Lightly edited for this site. I still keep the notebook from that summer: mostly definitions, a few diagrams, and one sentence underlined twice — start with the problem, not the model.
